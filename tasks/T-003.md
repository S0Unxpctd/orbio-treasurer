# T-003 · redact() + structured logger

Day: 0 · Layer: L0 · Estimate: 1.5h · Depends on: T-001 · PRD: PRD §11, FR-2.1

## Goal
One log() producing JSON lines with a mandatory redact() masking keys, OAuth tokens and private keys to prefix…last4.

## In scope
- redact.ts: sk-or-*, Bearer, 0x-prefixed 64-hex private keys, 32+ char blobs, env names ending _KEY/_SECRET/_TOKEN/_PK
- log.ts with levels and context
- Test asserting no console.log in packages/core

## Out of scope
- Third-party logging SDKs

## Acceptance criteria
1. redact('sk-or-v1-TESTONLYabcdef1234') === 'sk-or-…1234'; a 0x private key is fully masked
2. Nested objects and error stacks redacted
3. log() output is JSON and never contains a fixture secret

## Build notes
Built `packages/core/src/redact.ts` and `packages/core/src/log.ts`, both pure TS, no I/O beyond
`console.error`/`process.env`, no new dependencies.

- `redact(value)` deep-walks strings, arrays, plain objects and `Error` (message + stack, plus
  any extra own-enumerable props) and masks secret-shaped substrings via a sequential
  regex-replace pipeline (most specific pattern first, so an already-masked span — which
  contains `…` — can never be re-matched by a later, more generic pattern):
  1. `Bearer <token>` — keeps the scheme word, masks only the token (recursing into the same
     shape-detection used for a bare string).
  2. `sk-or-...` (Orbio/OpenRouter) → `sk-or-…<last4>`.
  3. generic `sk-...` → `sk-…<last4>`.
  4. `0x`+64-hex private key → `0x…<last4>` (fully masked; deliberately does NOT match
     `0x`+40-hex addresses, which stay public).
  5. JWT-looking `xxx.yyy.zzz` → `<first4>…<last4>`.
  6. opaque blob, `[A-Za-z0-9_-]{32,}` → `<first4>…<last4>`, EXCEPT when the candidate is a
     UUID, an `0x`+40-hex address, or purely digits — those are explicitly exempted so they
     survive unmasked.
  - Because this is a plain string scan (not URL- or stack-trace-aware), it finds secrets
    embedded in query strings, basic-auth userinfo, and Error messages/stacks for free — no
    special-cased URL parsing needed (see Audit focus below).
  - Any object key ending in `_KEY`/`_SECRET`/`_TOKEN`/`_PK`/`_PASSWORD` (case-insensitive)
    masks its *whole* value regardless of shape — a string gets the same masking as above (or
    a `<redacted>` placeholder if it doesn't match a known pattern and is short), a non-string
    (object/array/number/bool) becomes the literal `'[REDACTED]'`.
  - `REDACTION_PATTERNS` is exported (7 named regexes) for direct pattern-level testing.
- `log(level, msg, ctx?)` prints exactly one `JSON.stringify`'d line via `console.error`
  (Biome's `noConsole` rule allows only `"error"` in `packages/core`, confirmed in `biome.json`)
  with `{ ts: new Date().toISOString(), level, msg, ...redact(ctx) }`. `LOG_LEVEL` env var sets
  the threshold (`debug|info|warn|error`, default `info`); an unrecognized value falls back to
  `info` rather than throwing. `createLogger(baseCtx)` returns `{debug,info,warn,error}` methods
  that merge `baseCtx` under the per-call `ctx` (call-site wins on key conflict).
- Did not export `redact`/`log` from `packages/core/src/index.ts` — the ticket's "In scope"
  names only `redact.ts`/`log.ts`; leaving `index.ts` untouched avoids any file overlap with the
  concurrent T-002 builder. A follow-up ticket can wire the barrel export when core's public API
  is assembled.

### Fixes after audit 1 (`tasks/reports/T-003-audit-1.md`)

All 4 Blockers and all 3 Majors fixed; the Minor ("whitespace-split secrets") is intentionally
not fixed — documented as a known, accepted gap instead (see below).

- **[Blocker] `log()` didn't redact `msg`.** `log.ts` now does `msg: redact(msg, ...) as string`
  before building the line — a secret interpolated straight into the message string is masked
  exactly like one in `ctx`.
- **[Blocker] Non-plain values bypassed `redact()` entirely.** The dispatcher no longer has a
  silent `return value` fallthrough. It now explicitly handles: class instances (walked like a
  plain object, via `Object.keys` — same sensitive-key-name treatment applies), `Map` (→ array of
  `[redact(k), redact(v)]` entries), `Set` (→ array of `redact(v)` values), `Buffer`/`Uint8Array`/
  any `ArrayBufferView`/`ArrayBuffer` (→ `<bytes:N>`, byte length only, raw bytes never emitted —
  this was the most severe finding, since wallet private keys are routinely `Buffer`/`Uint8Array`
  in ethers.js/viem/web3.js), `BigInt` (→ `.toString()`), `Date` (→ `.toISOString()`), functions
  and symbols (→ `'<fn>'`).
- **[Blocker] `sk-or-`/`sk-` patterns were case-sensitive.** Added the `i` flag to
  `REDACTION_PATTERNS.openRouterKey`/`genericSecretKey`; `SK-OR-V1-...` now masks correctly
  (previously invisible to every layer since the 27-char fixture is below the 32-char
  opaque-blob fallback threshold).
- **[Blocker] Sensitive-key-name rule only matched SCREAMING_SNAKE/snake_case.** Added
  `REDACTION_PATTERNS.sensitiveKeyNameCamel`, exactly
  `/(api[_-]?key|secret|token|password|passwd|private[_-]?key|mnemonic|seed|pk)$/i`, matched
  case-insensitively alongside the existing `_KEY/_SECRET/_TOKEN/_PK/_PASSWORD` suffix rule.
  Covers `apiKey`, `clientSecret`, `dbPassword`, `refreshToken`, `mnemonic`/`seed`-suffixed
  fields, `privateKey`, and bare `pk` in any case.
- **[Major] Circular references threw `RangeError`.** `redact()` now takes a `seen: WeakSet<object>`
  (created fresh per top-level call, threaded through every recursive call) and returns
  `'<circular>'` for any object already in it instead of recursing. Deliberately conservative:
  it flags any *repeated* object reference this way, not only a true ancestor cycle — a rarer
  false positive (a shared, non-circular reference logged as `<circular>`) is preferable to the
  bookkeeping needed to distinguish it, and it's still strictly safer than the alternative
  (a crash, or infinite recursion).
- **[Major] `log()` threw uncaught on `BigInt`/circular ctx.** Both are now handled inside
  `redact()` (see above), and `log()` additionally wraps the whole build-line-and-stringify path
  in `try/catch`; on any remaining failure (e.g. a `ctx` property getter that itself throws — a
  case `redact()` doesn't special-case) it emits a fallback line
  `{ts, level:'error', msg:'log-serialization-failed', reason}` instead of throwing. `log()` is
  now unconditionally non-throwing.
- **[Major] `Error.cause` was silently dropped; other non-enumerable Error props too.**
  `redactError` now reads `err.cause` explicitly (redacted recursively) and walks
  `Object.getOwnPropertyNames(err)` (not `Object.keys`, which misses `message`/`stack`/`cause` —
  they're non-enumerable) for any other own props, skipping the four already handled.
- **[Major] 0x+64-hex ambiguity (private key vs. tx hash) was undiscussed.** Documented at the
  top of `redact.ts` under "0x + 64-hex ambiguity": the module fails closed (masks *every*
  0x+64-hex string by default, including a harmless tx hash) and exposes an explicit opt-out —
  `redact(value, { allowTxHashKeys: [...] })` — for call sites that know a given key name (e.g.
  `txHash`) holds a public hash, not a key. `DEFAULT_ALLOW_TX_HASH_KEYS = ['txHash', 'hash',
  'transactionHash']` is exported and `log.ts` now passes it by default, so a value logged under
  one of those key names is left intact while everything else still fails closed. This is a
  key-name allow-list only, never a content heuristic — a value's shape can never prove it isn't
  a private key.
- **[Minor, not fixed] Whitespace-split secrets.** `redact('sk-or-v1-TESTONLY abcdef1234')` still
  only masks the fragment up to the space. Documented at the top of `redact.ts` under "Known,
  accepted gap" per the audit's own framing ("don't bother, note it") — reassembling
  whitespace-broken tokens risks false positives on ordinary prose and wasn't asked for.

Test counts after these fixes: `redact.test.ts` 55 cases (27 original + 28 new adversarial/
non-plain-value cases, several via `it.each`), `log.test.ts` 22 cases (13 original + 9 new,
including the circular/BigInt/poisoned-getter/msg-redaction cases the coordinator asked for).

### Fixes after audit pass 2 (`tasks/reports/T-003-audit-1.md` "## Pass 2")

One Blocker: `allowTxHashKeys` exempted the **whole value** under a matching key name,
regardless of shape, with no recursion — so a real private key under `txHash`, a non-hash
secret under the (then-default) generic `hash` key, and a secret nested *inside* an
allow-listed key's object value all leaked raw through `log()`. This was a regression
introduced by the pass-1 fix itself, not a pass-1 leftover.

Fixed exactly per the coordinator's spec:
1. The exemption now requires **both** an exact (case-insensitive) key-name match **and** the
   value itself being a string matching `/^0x[0-9a-f]{64}$/i` — checked in a new
   `isExemptTxHashValue(key, value, options)`, replacing the key-only `isAllowedTxHashKey`.
2. Any value that fails either check (wrong key, or right key but wrong shape) falls straight
   through to the normal pipeline in `redactContainer` — `isSensitiveKeyName` then `redact()` —
   so `sk-*`/`Bearer`/JWT/opaque-blob patterns and sensitive-key-name masking all still apply
   to it, exactly as if no allow-list existed.
3. Because the exemption check now itself requires `typeof value === 'string'`, a non-string
   value under an allow-listed key (an object, array, etc.) never matches it and is always
   recursed into normally — a secret nested under `{ txHash: { apiKey } }` is now caught.
4. `DEFAULT_ALLOW_TX_HASH_KEYS` is now `['txHash', 'transactionHash', 'tx_hash',
   'transaction_hash']` — `'hash'` dropped (too generic to be a safe *default*, per the audit).
   `log.ts` needed no change: it already just imports and passes this constant through.

Updated the "0x + 64-hex ambiguity" header comment in `redact.ts` to spell out both axes of the
exemption (exact key name AND exact value shape) and explicitly say what happens on a
mismatch — the previous wording only described the key-name axis, which is exactly what let
the whole-value bypass go unnoticed as a design gap in pass 2.

Updated the existing "opts a key out of masking entirely, by name" test (renamed to say
"...but ONLY for an exact 0x+64-hex string value" — the old title asserted the now-fixed
whole-value semantics). Added a new `describe` block covering: a non-hex value under an
allow-listed key still masks, a nested object under an allow-listed key still recurses, `'hash'`
no longer bypasses anything, the exact default list contents, and the positive case (a genuine
tx-hash-shaped value under `transactionHash` stays intact) — plus two `log()`-level
counterparts reproducing the audit's exact repro shape through a real `log()` call.

Test counts after this fix: `redact.test.ts` 60 cases (55 + 5), `log.test.ts` 24 cases (22 + 2).
