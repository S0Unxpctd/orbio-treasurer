## Build notes
Read-only probe, 2026-09-09: curl (no auth, no cookies), ~26 requests, 1s apart. Checked `robots.txt`/`sitemap.xml`, homepage HTML/RSC payload, `/api/{book,orders,market,listings,credits,sales,orderbook}` on `www.orbio.so`, `/api/v1/{book,orders,market,listings,credits}` on the gateway, and `/book`, `/market`, `/credits`, `/leaderboard` pages. All `/api/*` candidates on both hosts → 404 (Next.js HTML 404 page, not JSON). `/credits` → 308 to `/` (homepage is the book page, no dedicated route). `/leaderboard` → 308 to `https://sellers.orbio.so/leaderboard` (200, but that's the leaderboard app, not the book/market). Full status matrix in the fixture.

Homepage (`GET https://www.orbio.so/`, 200, no auth) does embed live sales data — a recent settled-sales feed (`label` (masked email), `creditMicroUsd`, `discountBps`, `settledAt`) and a headline "$N,NNN credits available" figure — but only inside the Next.js RSC wire payload, not as a separate JSON response, and with no per-model breakdown or depth curve (FR-5.2's target shape isn't there). CSP `connect-src` on `www.orbio.so` allow-lists only self + Privy/WalletConnect/Tolt — no `api.orbio.so` or book host — confirming the browser itself never fetches book data from a separate JSON API.

**L1 default: `BOOK read = none`.** Per FR-5.2, L1 degrades to "no book data" this week; X post drops the book lines.

## Discovered
- The homepage's embedded RSC sales-feed data (recent settled sales with discount/amount/timestamp) could be a scrape-based best-effort fallback later, but it is not a stable contract (undocumented Next.js internal format, no per-model depth) — not proposing a ticket for this now; flagged as a future option only if Yash confirms no read endpoint is coming.
- `sellers.orbio.so` is a separate app (redirect target of `/leaderboard`); its root `/` 404s — likely gated behind auth for anything beyond `/leaderboard`. Not explored further (out of scope, would risk touching a login flow).
- MCP tool list as of 2026-09-09 includes a new `orbio_delete_key` tool (see `docs/api-notes.md` MCP section) — not previously recorded, behavior unprobed.
