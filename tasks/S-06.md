# S-06 · Tick + policy + wiring (the loop runs end to end)
Sprint 1.0 · Layer: L0 · Depends on: S-01, S-02, S-03, S-04, S-05 (all merged) · PRD: docs/PRD-1.0-sprint.md §1 (the loop), §4 T-6, §6 · MONEY TICKET → Code → Audit → Test

## Goal
Every 15 minutes the Treasurer reads its position, decides deterministically, acts within the gates, and records everything — and the gateway's router obeys the mode the policy chose. After this ticket the product is one deploy away from a live demo.

## In scope
- **Policy** `packages/core/src/policy/sprint.ts` (pure; keep the existing T-015 engine untouched, it is superseded — do not delete, do not call): `decide(input, config) → Decision` where input = `{snapshot: ChainSnapshot, apiBalance: {available, used}, burnDaily, callsSinceLastStakeup, buysToday, activatedToday, claimable, now, live: boolean}` and config = caps from `policy/defaults.ts` (+ new `STAKEUP_EVERY_CALLS = 1000`, `STAKEUP_USDG = '1'`, `RUNWAY_ECO_DAYS = 2`, `RUNWAY_CRITICAL_DAYS = 0.5`, `RUNWAY_BUY_DAYS = 1`).
  - `runwayDays = available / burnDaily` (decimal strings; ∞ when burn = ε and available > 0 → treat as 999).
  - `mode`: `normal` ≥ 2 d, `eco` < 2 d, `critical` < 0.5 d.
  - actions (ordered): `claim_activate` if claimable > 0 or staker CREDIT > 0 or hot CREDIT > 0; `buy` with `usdg = min(BUY_MAX_USDG_PER_TX, ceil(deficit))` where deficit = (RUNWAY_BUY_DAYS × burnDaily − available) when runway < 1 d and deficit > 1; `stakeup` when `callsSinceLastStakeup ≥ STAKEUP_EVERY_CALLS`. Each action carries `{reason, inputs}` so the decision can be re-derived (FR-4.6 spirit). Table-driven tests ≥ 15 rows.
- **Executors** `packages/core/src/tick/executors.ts`: map actions → S-04 `claimAndActivate`, S-05 `buyCredit`, and a `stakeup` executor that for this ticket only writes an `alert` event with the deep link (S-07 replaces it). Every action result → ledger; `mode` change → `mode_change` event; blocked action → `alert` with the gate reason. `dry_run` rows when live is off. Never throw past the tick: each executor error is caught, redacted, recorded, and the tick continues.
- **Tick** `packages/core/src/tick/tick.ts`: `runTick({store, agentSlug, now, env})`: idempotency bucket = 15-min UTC bucket (`YYYY-MM-DDTHH:MM` floored to 00/15/30/45); if a `chain_snapshot` for this agent with `meta.bucket` (add the bucket into `rpc_url_host`? no — write it into a `treasury_events` `dry_run`/`tick` marker row: add kind `tick` to the CHECK list via migration 006, both dialects) exists → return `{skipped:'duplicate'}`. Steps: `snapshotTreasury` (S-03) → `readApiBalance` (S-03, key from `getUpstreamKey`) → `burnDaily` + call counts (S-02) → `decide` → executors, all inside `store.withAgentLock(agentId)`. Returns a JSON summary (numbers, no secrets). Writes the mode into the agent's `policy` jsonb (`updateAgent` is not allowed on `policy` — so keep mode in the latest `chain_snapshots.mode` column, which S-02 already has, and the router reads it).
- **Router mode wiring**: `apps/web/app/v1/_gateway.ts` reads the current mode from `latestChainSnapshot(referenceAgent).mode` (cached 60 s) instead of `TREASURER_MODE` env; env still wins if set (for tests). Recorder: replace the JSONL/in-memory recorder with S-02's `LedgerCallRecorder` when a ledger is configured (adapter between the router `CallRecord` and the ledger one — the shapes differ, see `packages/core/src/index.ts` merge note; write the adapter in `packages/core/src/tick/recorder-adapter.ts` with tests). Caller keys: `CallerKeyStore` backed by S-02's `getCallerKeyByHash` when a ledger is configured, env keys still accepted as a fallback; add CLI `pnpm keys:create --label x` that inserts a key and prints it ONCE.
- **Route** `apps/web/app/api/tick/route.ts` (POST, header `x-tick-secret` must equal env `TICK_SECRET`, 401 otherwise) → `runTick` → JSON. `GET` returns 405. Runtime nodejs, `maxDuration = 60`.
- **Cron**: `supabase/migrations/006_tick_marker_and_cron.sql`: kind `tick` added to the CHECK; the existing `treasurer-tick` cron job (004) re-pointed to `POST app.tick_url` with header `x-tick-secret` = `app.tick_secret` via `pg_net` (`net.http_post`), every 15 min. Document in runbook the two `ALTER DATABASE … SET app.tick_url/app.tick_secret` statements So runs once.
- CLI `pnpm tick` runs one tick locally (dry-run unless env says otherwise; the CLI never flips live).
- `.env.example` + runbook updated with every new var: `TICK_SECRET`, `REFERENCE_AGENT_SLUG`, caps.

## Out of scope
- Stake-up execution (S-07). Kit (S-09). Page changes beyond what mode/tick rows already render (S-08 shows events and mode already).

## Acceptance criteria
1. `decide()` table-driven tests: mode thresholds at the exact boundaries; buy sizing (deficit → capped usdg, ceil); no buy when live off (action still emitted, executor turns it into dry_run — the policy is live-agnostic except for `inputs.live` being recorded); stakeup trigger; claim trigger from each of the three balances; ∞ runway.
2. `runTick` against fakes (fake chain client, fake gateway fetch, real SQLite store): writes 1 chain snapshot, N events, returns the summary; called twice in the same bucket → second returns `skipped:'duplicate'` and writes nothing.
3. Executor error isolation: a throwing `buyCredit` does not prevent `claimAndActivate` from running; the error is recorded redacted.
4. Router reads mode from the ledger: seed a snapshot with mode `critical` → `POST /v1/chat/completions` with `model:"auto:L"` is served by tier S (cap over floor) and the reason says so.
5. `LedgerCallRecorder` receives every gateway call (integration test through the route: one call → one `usage_events` row with `cost_usd`, `baseline_cost_usd`, `caller_key_id` set when the key came from the ledger).
6. `POST /api/tick` without the secret → 401; with it → 200 + summary; `GET` → 405.
7. Migration 006 applies twice on local Postgres; the cron job row has the new command (test by reading `cron.job`).
8. No secret in tick summary, logs, events (test).
9. Live: the first live tick is run by So's `ok live S-06` in this ticket, from the CLI, with `TREASURER_LIVE=true` set by So in his shell for that one run. Evidence = tx hashes pasted here by So. Until then all live paths are exercised against fakes only.

## Audit focus
Anything that can send a tx with live off; tick running twice (cron + manual) in one bucket; lock held across the whole tick (yes, intended — check it releases on throw); mode cache staleness on the router; caller-key lookup timing (hash compare, no key logged); `TICK_SECRET` compared in constant time; policy purity (no Date, no I/O).

## Discovered
- **`buyCredit()`'s own internal `store.withAgentLock(agentId, ...)` deadlocks when called from
  inside `runTick()`'s outer lock for the SAME agent** (SQLite's per-agent FIFO promise chain is
  not reentrant — a second call for the same agentId never starts before the first settles, and
  the first IS this call). Found via `tick.test.ts`'s mode-change test hanging past its timeout.
  Fixed additively: `BuyCreditDeps` gets an opt-in `skipOwnLock?: boolean` (default `false`,
  preserving S-05's CLI and `buy.test.ts` exactly as shipped); `tick/executors.ts`'s `runBuy()`
  sets it `true` (the tick already holds the lock for the whole body, per spec). New regression
  test in `chain/buy.ledger.test.ts` (2s timeout) proves the non-deadlocking path directly. Not
  caught by S-05's own tests because nothing there ever nests a second `withAgentLock` call for
  the same agent — this is a genuinely new interaction introduced by this ticket's own "hold the
  lock across the whole tick" requirement, not a latent bug in S-04/S-05.
- **Revocation-bypass gap, self-caught, no test forced it**: `LedgerStore.getCallerKeyByHash()`
  returns a revoked row unfiltered. `_gateway.ts`'s new `resolveCaller()` explicitly checks
  `row.revokedAt === null` before accepting a ledger-backed key — without it, a revoked key would
  have kept working through this new path. `router/keys.ts`'s own S-01 `authenticateBearer()`
  fallback was already correct; only this new path needed the check.
- **`readTreasury()`'s client parameter widened from the full real viem `PublicClient` to
  `Pick<PublicClient, 'multicall'|'readContract'|'getBalance'>` (new export `TreasuryReadClient`,
  `chain/read.ts`)** — `tick.ts` needed a narrower test-fake-satisfiable type than the full
  ~70-member `PublicClient`. A hand-rolled interface (mirroring `chain/buy.ts`'s `BuyExecClient`
  style) was tried first and rejected: viem's real `multicall`/`readContract` are heavily
  overloaded generics, not assignable from a simplified hand-rolled signature — it broke
  `read.test.ts` and `treasury-read.ts`'s real-client call sites. `Pick<PublicClient, ...>`
  preserves full real-client compatibility everywhere; the cost is one explicit
  `as unknown as TickExecClient & TreasuryReadClient` cast on `tick.test.ts`'s fake client
  (documented there — every method the fake needs is genuinely implemented).
