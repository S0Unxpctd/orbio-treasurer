## Build notes

Wrote `scripts/probes/p1-mcp-auth.ts`, runnable via `pnpm probe P-1`. Added
`@modelcontextprotocol/sdk` (^1.30.0, current) to the root `devDependencies` via
`pnpm add -D -w @modelcontextprotocol/sdk` — no other dependency added.

Design: discovery (RFC 9728 protected-resource, then RFC 8414/OIDC authorization-server
metadata) is done manually with the SDK's low-level `discoverOAuthProtectedResourceMetadata`
/ `discoverAuthorizationServerMetadata` so the script can print which one worked. The
interactive authorize-once step uses the SDK's `auth()` orchestrator with a custom
`OAuthClientProvider` backed by `.env.local` (PKCE S256, `state` generated and checked
against the pasted-back redirect URL). The unattended 6h polling loop deliberately does
**not** pass that provider to `StreamableHTTPClientTransport`: the SDK's built-in 401
handling falls through to starting a brand-new interactive authorization flow when a
refresh fails, which would block an unattended loop on stdin. Instead the loop sets the
`Authorization` header itself, catches 401 explicitly, and calls `refreshAuthorization()`
exactly once — matching the ticket's "attempt refresh once ... continue or stop".
Every log line is `JSON.stringify(redact({...}))`; `.env.local` is updated key-by-key
(`ORBIO_MCP_TOKEN`, `ORBIO_MCP_REFRESH_TOKEN`, `ORBIO_MCP_TOKEN_EXPIRES_AT`,
`ORBIO_MCP_CLIENT_ID`, `ORBIO_MCP_CLIENT_SECRET`) and re-chmod'ed 0600; no value is ever
logged.
