# S-03 · Treasury read (chain 4663) + wallet-signed Orbio key
Sprint 1.0 · Layer: L0 · Depends on: S-02 (merged) · PRD: docs/PRD-1.0-sprint.md §3 (all addresses, ABIs, key derivation), §4 T-3, §6

## Goal
The Treasurer can see its own position without any human step: staked ORBIO, claimable and wallet CREDIT, API balance, live book quote, gas and USDG balances — and can derive its own Orbio API key from its wallet.

## In scope
- `packages/core/src/chain/`: viem (allowed by ARCHITECTURE §1) with a `robinhoodChain` definition (id 4663, ETH gas, explorer `https://robin.etherscan.io`), a public client with an ordered RPC fallback list from env `RH_RPC_URLS` (comma-separated; default `https://robinhood-rpc.publicnode.com,https://rpc.ordofi.network`), and a `contracts.ts` that reads ALL addresses from env (`CREDIT_ADDRESS`, `STAKING_ADDRESS`, `EXCHANGE_ADDRESS`, `ORBIO_ADDRESS`, `USDG_ADDRESS`, `NVDA_ADDRESS`, `PAYOUT_ADDRESS`) — never hard-coded in source (CLAUDE.md #5). Put the PRD §3 values in `.env.example` and in `docs/runbook.md`.
- ABIs under `packages/core/abi/`: `credit.json`, `exchange.json`, `erc20.json` fetched from `https://www.orbio.so/protocol/abi/<name>.json` (commit the files, dated in a README); `staking.json` hand-written from the verified signatures in PRD §3 (stake, settle, claim, settledOf, positionOf, rewardOf, rewardPeriod, totalStaked, MIN_POSITION, PERIOD, addresses) — mark the unverified return shapes and confirm them with live read-only calls (they are free): record each call's raw redacted output in `docs/api-notes.md` under a dated "S-03 chain reads" section.
- `readTreasury({hot, staker}) → ChainSnapshot`: `positionOf(staker)`, `settledOf(staker)`, `CREDIT.balanceOf(hot)`, `CREDIT.balanceOf(staker)`, `USDG.balanceOf(hot)`, `getBalance(hot)` (ETH), `Exchange.getQuote(10e6, 10)` → `quoteCreditPerUsdg` (6-decimal string, null if the call reverts), `Staking.totalStaked()`, `MIN_POSITION()`, `PERIOD()`. All amounts as decimal strings of the raw integer (TokenAmount) — no floats. Uses `multicall` if available on 4663, else sequential with the fallback client.
- `readApiBalance(key) → {available, used}` from `GET ${ORBIO_GATEWAY_BASE_URL}/key` (Zod; strings). Also parse the `X-Orbio-Balance` header helper for S-06.
- Wallet-signed key: `deriveOrbioKey(privateKey, epoch=0)`: `sig = signMessage("Orbio API key · chain 4663 · epoch 0")` (exact string, note the middle dots U+00B7), key = `sk-orb-<epoch>-<base64(sig bytes)>`. Test with a throwaway private key: the derived key MUST be accepted by the gateway format-wise (call `/key` and record the status + redacted body in api-notes; a 200 with balance 0 or a 401 whose message says the key is unknown are both acceptable evidence — a 401 "malformed" is not). Never log the key: `redact()` must catch `sk-orb-` prefixes (extend redact's patterns if needed, with a test).
- `getUpstreamKey()` seam in `apps/web/app/v1/_gateway.ts`: if `TREASURER_PRIVATE_KEY` is set, use the derived key; else fall back to `ORBIO_KEY`. Env additions in `env.ts`: `TREASURER_PRIVATE_KEY`, `STAKER_ADDRESS`, `STAKER_PRIVATE_KEY` (optional), `RH_RPC_URLS`, the 7 address vars.
- `readTreasury` result persisted through `LedgerStore.insertChainSnapshot` (S-02) by a small `snapshotTreasury(store, agentId, now)` function; CLI `pnpm treasury:read` prints the snapshot (redacted, addresses shortened to 0x1234…abcd).

## Out of scope
- Any transaction (S-04, S-05, S-07). Policy (S-06). The page (S-08). `unstakeAll` and any unverified selector.

## Acceptance criteria
1. `readTreasury` returns a fully populated snapshot for the PRD §3 addresses with `staker` = any address that has a position (use `totalStaked()` and one known staker if So's address is not in env: read `Staking` events is not possible without archive; so use env `STAKER_ADDRESS` if present, else a zero-position read still returns a well-formed snapshot with zeros) — live run output pasted in Evidence, no secrets.
2. RPC fallback: unit test with a fake transport where the first RPC returns 429 and the second answers.
3. `getQuote(10 USDG)` live returns a quote (record `creditOut`, `fills`, discount %) or a typed `QuoteUnavailable` — Evidence shows which.
4. `deriveOrbioKey` is deterministic (same PK → same key, test with a throwaway PK) and the gateway accepts the format (Evidence).
5. `redact()` masks `sk-orb-…` keys and 0x private keys (64 hex) — tests.
6. All external payloads (RPC results decoded by viem; `/key` JSON) validated; `/key` unknown shape → `AdapterShapeError`.
7. `pnpm treasury:read` runs against the real chain and prints in < 10 s.

## Build notes
Branch `s-03` off `main` @ 6cab681. Added `viem` to `packages/core` (ARCHITECTURE.md §1), own commit.

Layout: `packages/core/src/chain/{chain,contracts,errors,key,read,snapshot}.ts` + `index.ts`
barrel, exported from `packages/core`'s own `index.ts` (`AdapterShapeError` aliased to
`ChainAdapterShapeError`, same reason `router/errors.ts` gives for not sharing `mcp/`'s). ABIs in
`packages/core/abi/` — `credit`/`exchange`/`erc20` fetched verbatim from
`www.orbio.so/protocol/abi/*.json` (2026-09-19), `staking.json` hand-written from PRD §3's
signatures (see `abi/README.md` for exactly what's verified vs. not).

`robinhoodChain` declares Multicall3 at the standard CREATE2 address — confirmed **deployed**
on 4663 via live `eth_getCode` (7618 bytes), so `readTreasury()` uses `client.multicall()` with
`allowFailure: true` for its 9 non-ETH reads and only falls back to 9 sequential `readContract`
calls if the multicall call itself throws (not merely one leg reverting — that's what
`allowFailure` already covers). `createRobinhoodClient()` wraps each RPC in a small tracking
transport so a resolved snapshot's `rpcUrlHost` reflects whichever RPC actually answered, not
just the first one tried.

`quote` is typed `QuoteResult | null` rather than a separate named `QuoteUnavailable` type (AC3
says "or a typed QuoteUnavailable") — `null` already forces every caller to handle the
unavailable case explicitly (same effect, no extra type), and it's exactly what
`snapshotTreasury()` needs to write `quoteCreditPerUsdg: null`. Flagging the wording difference
rather than silently declaring it identical.

`getUpstreamKey()` (router/upstream.ts, S-01) had to become `async` to call
`deriveOrbioKey()` — its two apps/web call sites (`_gateway.ts`, `chat/completions/route.ts`) now
`await` it. This is exactly the seam the ticket names in scope ("`getUpstreamKey()` seam in
apps/web/app/v1/_gateway.ts: if `TREASURER_PRIVATE_KEY` is set, use the derived key; else fall
back to `ORBIO_KEY`"), not scope creep — flagging the async signature change since it touches
S-01's code, not just S-03's own package.

`readApiBalance()` distinguishes a shape problem (`AdapterShapeError`, 2xx body missing
`balance.available`/`used`) from an HTTP failure (`GatewayKeyHttpError`, any non-2xx, redacted
body attached) — a 401 "unknown key" is expected/normal for an unactivated wallet, not itself an
adapter-shape bug.

## Discovered
- **PRD doc casing bug**: `docs/PRD-1.0-sprint.md §3`'s printed USDG address
  (`0x5fc5360d0400a0Fd4f2af552ADD042D716F1d168`, lowercase `d` right after `5fc5360`) is not a
  valid EIP-55 checksum — the correct checksum is
  `0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168` (uppercase `D`), confirmed via viem's
  `getAddress()` and matching this session's own project-instructions header. Same address
  either way (`loadChainAddresses()` re-checksums regardless of input casing, so nothing broke),
  but the PRD text itself should get the correct casing so nobody hand-copies it somewhere that
  *does* do a strict comparison. `.env.example`/`runbook.md` use the corrected casing.
- The real `exchange.json` ABI's `getQuote` returns the full `{creditOut, usdgSpent, feeAtoms,
  fills, reason}` tuple — richer than PRD §3's `(creditOut, fills)` shorthand. Decoded and used
  the full tuple; `ChainSnapshot.quote` carries all five fields.
- Multicall3 is confirmed deployed on chain 4663 at the standard address (not previously
  documented anywhere in the repo) — worth knowing for S-04/S-05/S-07's gas planning too.
- Extended `biome.json`'s existing `scripts/**` console-allow override to
  `packages/core/scripts/**` (same category of file, just nested under a package) so
  `treasury-read.ts`'s `console.log` isn't flagged the way `core/src`'s is.
- `GET /key`'s `rate_limit: {requests_per_minute, concurrent}` (PRD §3) is parsed-and-ignored by
  `readApiBalance()` (`.passthrough()`) — not surfaced anywhere. Not in this ticket's scope, but
  S-06 (policy) or the router may eventually want it.
