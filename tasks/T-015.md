# T-015 · Policy engine: evaluate(), states, funding options, humanize()

Day: 2 · Layer: L0 · Estimate: 4.5h · Depends on: T-011 · PRD: FR-4.1..FR-4.7, FR-11.3, PRD §10

## Goal
Pure policy function implementing PRD §10 incl. option selection between BUY_CREDIT, STAKE_UP and SIGNAL_FUND by cost/payback; stable rule ids; hysteresis; template human strings.

## In scope
- policy/evaluate.ts, rules/*.ts, defaults.ts, humanize.ts
- Decision type with inputs/action/rule_id
- Payback computation and stake_payback_max_days gate
- Hysteresis (2 ticks, except into DEFICIT)

## Out of scope
- I/O
- Executors (T-016)

## Acceptance criteria
1. 100% branch coverage on evaluate()
2. Table tests: each state × {book write on/off} × {stake on/off} × {caps exhausted} × {stable balance below reserve}
3. Property test: re-evaluating stored inputs reproduces the decision (200 random snapshots)
4. evaluate() < 5ms

## Audit focus
- Math vs §10: ε, ∞, caps counting bought_today/staked_today, payback_days
- Any I/O import

## Tests required
- unit: policy/*.test.ts, property test

BUY_CREDIT if present and need can be covered today, else STAKE_UP" is read as "prefer
BUY_CREDIT whenever it's in `options`", not as an extra gate on the buy amount fully covering
`need` — matches FR-4.3's ordered list and the stated rationale (credit is faster than a
multi-day payback). A dedicated test locks this reading (`'book on + stake on ... → BUY_CREDIT

## Discovered
- `index.ts` doesn't export anything from `policy/` yet — out of this ticket's In scope file
  list. T-016 (executors) will need `evaluate`, `DEFAULT_POLICY` and the policy types exported;
  add the barrel exports there or in a small follow-up when wiring the first consumer.
- FR-4.8's "reserve" in `forecast_usd_next_window > credits_available − reserve` has no PRD
  number. Added `policy.prebuyReserveUsd`, default `'0'` (conservative — never under-buys
  relative to the PRD formula). Flagging for So in case a nonzero reserve was intended.
- `book.bestDiscountPct` / `stake.yieldPerTokenPerDay` units: treated `bestDiscountPct` as a
  whole percent (e.g. "35" = 35%, matching the `Pct` suffix in `BookSnapshotRow`), converted to
  a fraction internally for the `1 − best_discount` cost formula. If the real book adapter
  (T-016+) returns a 0..1 fraction instead, the conversion in `rules/money.ts`
  (`percentToFraction`) needs to be dropped, not the caller.
- The ticket header cites PRD FR-4.1..FR-4.7; the orchestrator brief additionally named FR-4.8
  (predictive prebuy). Built FR-4.8 since it's a policy rule and PRD wins over the ticket
  header on requirement coverage — flagging in case FR-4.8 was meant for a later ticket.
