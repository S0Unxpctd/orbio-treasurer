# T-015 · Policy engine: evaluate(), states, funding options, humanize()

Day: 2 · Layer: L0 · Estimate: 4.5h · Depends on: T-011 · PRD: FR-4.1..FR-4.8, FR-11.3, PRD §10

## Goal
Pure policy function implementing PRD §10 incl. option selection between BUY_CREDIT, STAKE_UP and SIGNAL_FUND by cost/payback; stable rule ids; hysteresis; template human strings.

## In scope
- policy/evaluate.ts, rules/*.ts, defaults.ts, humanize.ts
- Decision type with inputs/action/rule_id
- Payback computation and stake_payback_max_days gate
- Hysteresis (2 ticks, except into DEFICIT)

## Out of scope
- I/O
- Executors (T-016)

## Acceptance criteria
1. 100% branch coverage on evaluate()
2. Table tests: each state × {book write on/off} × {stake on/off} × {caps exhausted} × {stable balance below reserve}
3. Property test: re-evaluating stored inputs reproduces the decision (200 random snapshots)
4. evaluate() < 5ms

## Audit focus
- Math vs §10: ε, ∞, caps counting bought_today/staked_today, payback_days
- Any I/O import

## Tests required
- unit: policy/*.test.ts, property test

### Fixes after audit 1

**M1 (`ALERT_DEFICIT_UNFUNDED`)** — added `hysteresis.previouslyUnfundedInDeficit: boolean |
null` (`types.ts`), tracked by the caller the same way `tick.mcpPreviouslyReachable` tracks MCP
reachability. `evaluate.ts`'s DEFICIT branch now fires the alert whenever
`previouslyUnfundedInDeficit !== true` (covers both a fresh entry into DEFICIT and a
funded→unfunded flip mid-streak), instead of gating on `stateBefore !== 'DEFICIT'`. New tests:
"audit-1 M1: ALERT_DEFICIT_UNFUNDED fires again on a funded→unfunded flip mid-DEFICIT-streak"
and "a funded DEFICIT tick emits no SIGNAL_FUND/ALERT_DEFICIT_UNFUNDED regardless of
previouslyUnfundedInDeficit" (`evaluate.test.ts`).

**M2 (option selection)** — `rules/deficit.ts`'s `pickDeficitOption` now takes `needUsd` and
picks BUY_CREDIT only when `parseDecimal(buy.action.usd) >= parseDecimal(needUsd)` (i.e. it
fully covers `need`, not merely "present"); otherwise STAKE_UP if present; otherwise `null`
(SIGNAL_FUND) — including when a present-but-partial BUY_CREDIT exists and STAKE_UP doesn't
qualify. The module's header comment now quotes §10's line verbatim and states explicitly that
no cost comparison is added beyond it: ADR-003's "by cost" is read as satisfied by STAKE_UP's
own `payback_days ≤ stake_payback_max_days` gate (its cost ceiling), since §10 specifies no
other comparison and none should be invented. New describe block `'M2: §10 literal option
selection (audit-1 arbitration)'` covers: partial BUY_CREDIT + qualifying STAKE_UP → STAKE_UP;
partial BUY_CREDIT + no STAKE_UP → SIGNAL_FUND (not the partial buy); BUY_CREDIT exactly
covering `need` → BUY_CREDIT (still preferred over an available STAKE_UP). The pre-existing
"needUsd caps BUY_CREDIT..." test was rewritten to assert on `computeDeficitOptions()` directly
(the amount-capping formula, independent of which option `evaluate()` selects), since at its
old numbers the capped buy no longer fully covers `need` and is thus no longer the one
selected — exactly the behavior M2 changed.

**M3 (scope)** — ticket header's `PRD:` line changed to `FR-4.1..FR-4.8`; one-line note above
("FR-4.8 included on orchestrator instruction per PRD 0.3.1"). No code change.

**Minors (no code change, per arbitration)** — `prebuyReserveUsd='0'` and `bestDiscountPct`'s
whole-percent convention left as-is; both were already named below in Discovered as open
questions for So (m2, m3 in the audit report) and stay that way.

All DEFICIT-matrix test rows were re-checked against the new M2 selection logic: every existing
row's `need` (baseline DEFICIT numbers: credits=27, burn=10, accrual=0 → `need=3`) stays well
inside the default `max_buy_usd_per_day` (10), so a present, uncapped BUY_CREDIT always still
fully covers it — none of the 10 original rows changed expected outcome; three new tests were
added specifically to exercise the previously-untested partial-coverage fork.

`pnpm test` after fixes: 481 passed / 50 skipped (was 476/50 before this fix pass; +5 new
tests: 3 for M2's option-selection fork, 2 for M1's unfunded-flip alert).

## Discovered

  list. T-016 (executors) will need `evaluate`, `DEFAULT_POLICY` and the policy types exported;
  add the barrel exports there or in a small follow-up when wiring the first consumer.
- FR-4.8's "reserve" in `forecast_usd_next_window > credits_available − reserve` has no PRD
  number. `policy.prebuyReserveUsd` stays `'0'` (conservative — never under-buys relative to

  nonzero reserve intended?
- `book.bestDiscountPct` / `stake.yieldPerTokenPerDay` units: treated `bestDiscountPct` as a
  whole percent (e.g. "35" = 35%, matching the `Pct` suffix in `BookSnapshotRow`), converted to
  a fraction internally for the `1 − best_discount` cost formula, kept as-is per audit-1
  arbitration (minor, no code change). The auditor notes the one real field observed so far
  (`docs/api-notes.md`, P-3 probe) is `discountBps` (basis points) — neither of the two
  conventions considered here. **Question for So**: confirm the unit `BookClient` will actually
  return; whoever wires the real adapter (T-016+) needs a `bps → whole percent` (÷100)
  conversion before this input either way, and the conversion point (`rules/money.ts`'s
  `percentToFraction`) is isolated and cheap to change once confirmed.
- Ticket header now reads `FR-4.1..FR-4.8` (fixed per audit-1 M3) — no longer a discrepancy.
