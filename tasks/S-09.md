# S-09 · Kit (`npx create-orbio-agent`) + demo agent
Sprint 1.0 · Layer: L0 · Depends on: S-01, S-06, S-08 (merged) · PRD: docs/PRD-1.0-sprint.md §4 T-9, §1

## Goal
A stranger runs one command, gets a cron agent that calls the Treasurer gateway with `model:"auto"`, registers itself, and shows up on the public page within a minute — with no database account and no chain knowledge.

## In scope
- `packages/create-orbio-agent` (stub exists): a small Node CLI (`bin`: `create-orbio-agent`), no dependencies beyond Node 22 built-ins. `npx create-orbio-agent my-agent` copies `template/` into `./my-agent`, substitutes the name, prints next steps. Flags: `--gateway <url>` (default `https://<REFERENCE_HOST>` read from `packages/create-orbio-agent/defaults.json`, which S-10 sets to the Vercel URL), `--key <otk_…>` (optional; else the README says how to get one).
- `template/`: `package.json` (deps: none; uses global `fetch`), `agent.mjs` — runs one task: fetch 1–3 RSS/Atom feeds from `FEEDS` env (default two public tech feeds), build a prompt, call `POST ${ORBIO_TREASURER_URL}/v1/chat/completions` with `model: "auto"`, `x-baseline-model` optional, print the summary, POST it to `DIGEST_WEBHOOK_URL` if set; exits non-zero on gateway error. `register.mjs` — `POST ${ORBIO_TREASURER_URL}/api/agents` with `{name, repoUrl}` using the key; idempotent (second run is a no-op if 200/409). `cron.example` (crontab line `0 8 * * *`) and a GitHub Actions workflow `.github/workflows/daily.yml` (schedule + `workflow_dispatch`, secrets `ORBIO_TREASURER_KEY`) so the demo runs without a server. `.env.example`, `README.md` (5 lines to run; what "auto" does; where the savings show; the honest v1 caveat sentence from PRD §1).
- `examples/daily-digest`: the template instantiated (kept in sync by a test that diffs it against the generator output), used as the reference demo agent. X posting only via an optional `X_WEBHOOK_URL`-style hook — no X SDK, no keys required.
- Rename `apps/book-daily` → leave it; it is obsolete: add a one-line README note "superseded by examples/daily-digest (Sprint 1.0)". Do not delete.
- Gateway side (already exists): nothing to build; if `/api/agents` needs `repoUrl` vs `url` alias consistency (S-08 Discovered), fix the template to send `repoUrl`.

## Out of scope
- npm publish (S-10 / So). Multi-task agents. Payments. SQLite ledger in the kit (the kit is a *caller*, it has no ledger; the Treasurer meters it server-side — this supersedes CLAUDE.md 5c for this package: the kit needs neither DB nor SQLite).

## Acceptance criteria
1. In a clean temp dir: `node packages/create-orbio-agent/bin/create-orbio-agent.js demo --gateway http://127.0.0.1:<port> --key otk_TESTONLY…` creates the folder with all template files, name substituted (test).
2. With a local gateway (Next dev or the route handlers behind a tiny http server, fake upstream from S-01 tests) and a fake RSS server: `node agent.mjs` prints a summary and the gateway recorded one `usage_events` row with `routed_model` in tier S/M; `node register.mjs` creates the agent row; `GET /api/agents` lists it (integration test).
3. `register.mjs` run twice → still exactly one agent row.
4. Gateway down → `agent.mjs` exits 1 with a one-line error, no stack trace, no key in output.
5. `examples/daily-digest` equals the generator output for name `daily-digest` (diff test).
6. README quickstart verified by actually following it in the test (the 5 commands).
7. No secret in any committed file; `.env.example` only.

## Build notes
- `packages/create-orbio-agent` is now a plain-JS CLI, no build step: `bin/create-orbio-agent.js`
  runs directly with `node` (matches AC1's literal invocation). `package.json`'s `bin` points at
  it; `src/*.ts` is test-only now (the old `src/index.ts` stub is deleted), so `tsconfig.json`
  dropped `rootDir`/`outDir`/the test exclusion — it typechecks the two `.test.ts` files with
  `noEmit`, nothing is compiled to `dist`.
- Scaffolding: `scaffold()` copies `template/` into `./<name>`, substituting `__AGENT_NAME__` and
  `__GATEWAY_URL__` in every file's text. `--gateway` defaults to `defaults.json`'s `gatewayUrl`
  (currently the literal placeholder `https://<REFERENCE_HOST>` per the ticket's own notation —
  **S-10 must set this to the real Vercel URL** before `npm publish`).
- AC7 (no secret in a committed file), by construction rather than by care: the template ships
  no `__AGENT_KEY__`-shaped token at all, so there is no code path that could ever substitute a
  real key into `.env.example`. A key passed via `--key` is written to a *separate*, freshly
  created `.env` (never derived from a template file), and `template/.gitignore` (copied into
  every scaffold) keeps that `.env` out of the user's own git history. `examples/daily-digest`
  was generated with no `--key`, so it has no `.env` — confirmed by `cli.test.ts`'s "ship no
  secret at all" test, which greps every committed file in both `template/` and
  `examples/daily-digest/`.
- `register.mjs`'s idempotency (AC3) is client-side, deliberately: `/api/agents` POST creates a
  **new** `agents` row on every call when the caller key has no ledger-backed `agentId` (S-01's
  `EnvCallerKeyStore` always returns `agentId: null` — see `apps/web/app/api/agents/route.ts`'s
  own doc comment), so calling it twice would otherwise make two rows. `register.mjs` writes a
  local marker file (`.orbio-agent.json`, git-ignored) after its first successful call and treats
  any later run as a no-op purely from that marker's presence — this is what actually keeps the
  ticket's "still exactly one agent row" true, not anything server-side. See *Discovered* for the
  one place this doesn't hold.
- `agent.mjs` has zero deps: RSS/Atom titles are pulled with a small regex (`<title>` tags,
  CDATA/entity-unescaped, feed's own title skipped), not an XML parser. `--env-file=.env`
  (Node 22 built-in, stable) is the env loader — no `dotenv` package, matches "no dependencies
  beyond Node 22 built-ins".
- Discovered the gateway's actual alias precedence while building `register.mjs` (already fixed
  by S-08, not by this ticket — see that file's own doc comment): `repoUrl` wins over `url`, and
  the ticket's own body shape `{name, repoUrl}` is exactly what the current server expects, so no
  gateway-side change was needed here; `register.mjs` sends `repoUrl` from an optional
  `AGENT_REPO_URL` env var (not in the PRD text verbatim, but the field is optional in the
  server's zod schema, so a scaffold with no known repo just omits it).
- `apps/book-daily/README.md` added (one line, per ticket); the app itself is untouched, not
  renamed, not deleted.
- `examples/daily-digest` is not a pnpm workspace member (outside `packages/*`/`apps/*` in
  `pnpm-workspace.yaml`, deliberately — it has zero deps, nothing to install) and is generated
  *by* the CLI (`node packages/create-orbio-agent/bin/create-orbio-agent.js daily-digest`, no
  flags), not hand-written, so it is byte-identical to the generator by construction; `cli.test.ts`
  still asserts this on every run rather than trusting that.
- `biome.json`: added `examples/**` to the `noConsole`-off override list (same as
  `packages/create-orbio-agent/**` already had) — `agent.mjs`/`register.mjs` there use
  `console.log` for their actual output, same as the template.

## Discovered
- **AC3's client-side idempotency doesn't survive `.github/workflows/daily.yml`.** Each GitHub
  Actions run is a fresh checkout with no persisted `.orbio-agent.json`, so the shipped workflow's
  `register.mjs` step would re-POST (and, with today's env-store keys, create a new `agents` row)
  every day it runs — unlike a long-lived cron box, which keeps the marker file and stays at one
  row. This is a server-side gap (`/api/agents` only updates-in-place when `caller.agentId` is
  set, which env-store keys never are — S-02/S-06's DB-backed caller keys fix it once they land),
  not something this ticket's "In scope" covers (Gateway side: "already exists, nothing to
  build" except the alias fix, which turned out to already be done). Flagging for whoever picks
  up S-02/S-06 caller-key persistence, or a follow-up ticket if that's still open by submission.
- `next dev` (Next 16, webpack mode) runs one *persistent* dev server per directory — killing the
  spawned CLI process does not stop the actual `next-server` worker, and a second `next dev` in
  the same directory refuses to start while `.next/dev/lock` names a live pid. `e2e.test.ts`'s
  `stopGateway()` kills both and removes the lock; worth knowing for any other ticket that spins
  up a real `apps/web` dev server in a test.
- `spawnSync` for a child that must reach an in-process fake HTTP server (this ticket's fake RSS
  server, S-01's `startFakeUpstream`) deadlocks: it blocks the test process's event loop, which is
  also what the in-process server needs to answer the child's request. `e2e.test.ts` uses an
  async `spawn()` + exit-event wait everywhere for this reason — a note for any future test that
  combines a real child process with an in-process fake server.
