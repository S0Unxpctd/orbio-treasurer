# S-08 · Public page `/`, `/api/stats`, `/api/agents`
Sprint 1.0 · Layer: L0 · Depends on: S-02, S-03 (merged) · PRD: docs/PRD-1.0-sprint.md §4 T-8, §1 (honest framing), §8

## Goal
Anyone (judge, Yash, a builder) opens the root URL and sees, without logging in: how much the gateway saved its callers, what the treasury holds and did on-chain (with explorer links), which agents run on it — and the honest v1 caveat.

## In scope
- `apps/web/app/page.tsx` (server component, `dynamic = 'force-dynamic'`, revalidate 60 s via `unstable_cache` or `Cache-Control: s-maxage=60`): reads through `LedgerStore` (Postgres in hosted mode; SQLite if `LEDGER=sqlite` so the page also works locally) for the reference agent (env `REFERENCE_AGENT_SLUG`, default `treasurer`; if the agent row does not exist, render the page with zeros and a "no data yet" note, never crash).
  - **Savings block**: calls routed, $ spent, $ baseline, $ saved, % saved — for 24h and all-time (S-02 `savings()`), plus a per-tier line (S / M / L: calls and $).
  - **Treasury block**: from `latestChainSnapshot`: staked ORBIO (18 dp, shown with 2 decimals and thousands separators), CREDIT claimable (settled), CREDIT in wallet, API balance available/used, live book quote as "10 USDG → X CREDIT (Y% discount)" or "quote unavailable", ETH gas, USDG, mode, runway days = available / burnDaily (S-02), snapshot age ("2 min ago").
  - **Proof block**: last 20 `treasury_events` (kind, amount + token, usd_value, time, `tx_hash` linked to `https://robin.etherscan.io/tx/<hash>`; dry_run rows shown greyed with their reason). Empty state: "No on-chain action yet".
  - **Agents block**: rows from `agents` where `public = true` (name, slug, last seen, link if `repoUrl`). Empty state with the kit one-liner `npx create-orbio-agent my-agent`.
  - **Footer** (verbatim, PRD §1): "v1: the buy-and-stake leg is funded by seed capital and capped; caller billing is not live. Every on-chain action above links to its transaction."
  - Plain JSX + one `globals.css`: dark background, system font, max-width 960px, readable on a 390px-wide phone, no client JS, no chart library, no external assets. Numbers formatted server-side from decimal strings (no float math for money: format only).
- `apps/web/app/api/stats/route.ts` (GET): JSON `{agent, savings: {h24, all, byTier}, treasury: <snapshot or null>, events: [...20], generatedAt}` with `Cache-Control: public, s-maxage=60`. Same data as the page.
- `apps/web/app/api/agents/route.ts`: GET → public agents list (JSON); POST `{name, url?, repoUrl?}` with `Authorization: Bearer otk_…` (validated through S-01's `CallerKeyStore`, env-backed for now) → upserts an `agents` row keyed by the caller key's `agentId` (or creates one with `slug` = slugified name + 4 random chars) and returns it. Zod on the body; 401/400 on failure; rate: reject bodies > 2 KB.
- Smoke: `pnpm smoke` becomes a real script (Node `fetch`, no Playwright) hitting `/`, `/api/stats`, `/api/agents` on `$SMOKE_BASE_URL` (default `http://localhost:3000`) and asserting 200 + the footer sentence + JSON shape.

## Out of scope
- Tick/policy (S-06), the kit itself (S-09), per-agent pages, charts, auth for viewing, i18n.

## Acceptance criteria
1. Fresh SQLite ledger with no agent → `/` returns 200 with zeros and the "no data yet" note (test with Next's route handlers + a temp SQLite path; or a rendered-HTML string test of the page's data→view function — keep the view a pure function `renderModel(data) → props` that is unit-tested, and the page thin).
2. With a seeded ledger (10 usage events, 1 chain snapshot, 3 treasury events incl. one dry_run, 2 agents one private): savings numbers equal S-02's `savings()` output; treasury numbers formatted as specified; exactly 2 proof rows with explorer links + 1 greyed dry-run row; exactly 1 agent listed.
3. `/api/stats` JSON validated by a Zod schema in the test; `Cache-Control` present.
4. `/api/agents` POST without key → 401; with key → 200 and a row exists; malformed body → 400; GET lists only public agents.
5. Footer sentence present verbatim in the HTML.
6. `pnpm smoke` passes against `next dev` started in the test (or documented as run manually with the output pasted in Evidence).
7. No secret, no private address material beyond what is already public on-chain (addresses shown shortened `0x1234…abcd`; full address only inside the explorer link).

## Build notes
- `apps/web/app/model.ts` — pure `renderModel(input) -> RenderModel`, unit-tested in
  `model.test.ts` (16 tests). Savings numbers (`savings.h24`/`.all`) are passed through from
  `savings()` byte-for-byte (raw fields), with a separate `*Display` field for the 2dp/$-prefixed
  presentation — this is what makes AC2 ("savings numbers equal S-02's savings() output")
  unambiguous: the raw fields ARE the SavingsResult. Treasury/token amounts get an explicit
  display transform (BigInt-only: `formatTokenAmount`/`formatMoneyDp`/`formatPercentLabel`, all
  round-half-away-from-zero, no `Number`/`parseFloat` anywhere) per the ticket's "18 dp, shown
  with 2 decimals and thousands separators" line, generalised to CREDIT/USDG/ETH too.
- `apps/web/app/_data.ts` (`loadRenderModelInput`) is the one place that touches `LedgerStore`:
  looks up `REFERENCE_AGENT_SLUG` (new env var, `packages/core/src/env.ts`, default `treasurer`),
  and on a missing agent returns zero-shaped input (AC1) without ever calling `savings()`/
  `burnDaily()` with a null agentId. `apps/web/app/_ledger.ts` (`getLedgerStore`) opens/caches the
  `LedgerStore` for the process, requiring `DATABASE_URL` for `LEDGER=postgres` (see Discovered).
- `apps/web/app/page.tsx`: thin server component, `dynamic = 'force-dynamic'` +
  `unstable_cache(..., { revalidate: 60 })` around the data fetch (the ticket's two named options
  combined: dynamic render, cached data). Falls back to the same zero model on any thrown error
  (env/ledger) — never crashes. Plain JSX + `globals.css` (dark, system font, 960px max-width, no
  client JS/chart lib/external assets).
- `apps/web/app/api/stats/route.ts`: `{agent, savings: {h24, all, byTier}, treasury, events,
  agents, generatedAt}`, `Cache-Control: public, s-maxage=60`.
- `apps/web/app/api/agents/route.ts`: GET is public; POST authenticates via S-01's
  `authenticateBearer`/`EnvCallerKeyStore` (env-backed, per the ticket), Zod-validates
  `{name, url?, repoUrl?}`, rejects bodies > 2KB by byte length, and since `EnvCallerKeyStore`
  always returns `agentId: null` today, every successful POST takes the "create one" branch
  (slug = slugify(name) + 4 random hex, retried on collision). The `caller.agentId` branch is
  written and ready for when S-02's DB-backed caller keys land.
- Root `pnpm smoke` (`package.json`) now runs `scripts/smoke.ts` (Node `fetch`, no Playwright)
  against `$SMOKE_BASE_URL`, hitting `/`, `/api/stats`, `/api/agents` + a 401 check.

## Discovered
1. **`next dev`/`next build` could not run this app at all before this ticket — sprint-wide, not
   S-08-specific.** Nobody had actually booted a real Next dev/build server for `apps/web` before
   (every existing route test, S-01 included, calls the route handler function directly and never
   goes through Next's bundler). Doing that for AC6 surfaced three separate, real bugs that would
   have broken `next build`/Vercel for every route, including S-01's already-merged ones:
   1. Every relative import written `./foo.js` (the repo's NodeNext/ESM convention — `tsc`/Vitest
      resolve it to `./foo.ts`) 500s under both of Next 16's bundlers ("Module not found") — fixed
      with `resolve.extensionAlias` in `apps/web/next.config.ts`'s `webpack()` hook (webpack only —
      Turbopack, the `next dev` default, needs its own fix; not attempted here, so **run
      `next dev --webpack` / `next build --webpack` until someone does**).
   2. `packages/core/src/ledger/sqlite/store.ts`'s `readFileSync(new URL('./schema.sql',
      import.meta.url))` throws `ERR_INVALID_ARG_TYPE` under webpack (the bundled URL instance
      fails Node's `instanceof URL` check) and, separately, webpack pattern-matches that exact
      `new URL('literal', import.meta.url)` shape as a static-asset import and rewrites it to an
      emitted `/_next/static/...` path. Fixed by routing `import.meta.url` through a variable
      first (defeats the asset-import pattern match) and reading `.pathname` (avoids the
      `instanceof URL` check) instead of `fileURLToPath`.
   3. `better-sqlite3`'s native `.node` addon doesn't survive webpack bundling even though it's
      already in Next's own default `serverExternalPackages` list (reproduced under `next build
      --webpack && next start` too, not just dev — see Evidence). Added `serverExternalPackages:
      ['better-sqlite3']` (belt) and a manual `config.externals.push('better-sqlite3')` in the
      `webpack()` hook for `isServer` (suspenders — the belt alone did not fix it in this pnpm
      workspace, root cause not fully diagnosed). **This only affects `LEDGER=sqlite`**; the
      hosted reference deployment uses `LEDGER=postgres` (the `postgres` npm package is pure JS,
      no native addon), so it's very unlikely to hit this — but the **kit** (S-09,
      `create-orbio-agent`, SQLite-only per CLAUDE.md #5c) runs a real Next server too and WILL
      hit it unless S-09 ships the same `next.config.ts` fix (or copies these three fixes into its
      template's own config). Flagging for S-09 and for T-10/submission: confirm the fixes carry
      into the kit template, and that a real `LEDGER=postgres` Vercel deploy doesn't have its own
      analog of #3 for the `postgres` package (reasoned to be unlikely, not verified — no
      `TEST_DATABASE_URL` in this sandbox).
2. `LedgerStore` had no way to list `agents` at all — needed a `listPublicAgents()` method for the
   Agents block (AC2's "exactly 1 agent listed") and for `/api/agents` GET. Added to
   `packages/core/src/ledger/types.ts` (+ SQLite/Postgres implementations + one conformance test),
   same "necessary infrastructure, not itself an S-02/S-03 AC" footnote `listUsageEvents` already
   carries.
3. The ticket's POST body is `{name, url?, repoUrl?}`, but the `agents` table has only a
   `repo_url` column, no generic `url` — matching PRD §4 T-9's kit, which posts `{name, url}`.
   `url` is accepted as an alias for `repoUrl` (repoUrl wins if both given) rather than dropped —
   see `api/agents/route.ts`'s doc comment. Flag for whoever builds S-09's register step.
4. `next dev` regenerates `apps/web/AGENTS.md`/`CLAUDE.md` on every run (Next's own
   `generate-agent-files.js`) and its own message says committing them keeps the tree clean since
   otherwise every future `next dev` re-dirties the same diff — committed as instructed by Next
   itself, not authored by me.
5. Interpreted `/api/stats`'s `savings.byTier` (a single top-level field, distinct from `h24`/
   `all`) as the all-time breakdown (`savingsAll.byTier`) — the ticket's page description shows
   one per-tier line, not one per window, and this is the only reading consistent with that.
