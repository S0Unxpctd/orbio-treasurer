# T-012 · BookClient interface + SignalsBookClient (read)

Day: 1 · Layer: L1 · Estimate: 3h · Depends on: T-003 · PRD: FR-5.1, FR-5.2

## Goal
The BookClient seam and a read-only implementation that fetches the book from the read API if configured, else parses the public page, normalizes to BookView, and records book_snapshots.

## In scope
- book/types.ts (BookClient, BookView, Fill, requests)
- SignalsBookClient with two sources: api | page
- Page parser isolated in book/page-parser.ts with dated HTML fixtures
- stale=true fallback to last snapshot on failure
- Write methods throw NotSupported

## Out of scope
- Any write path (T-020)
- Deep-link generation (T-021)

## Acceptance criteria
1. BookView for the current real book produced from both sources (page today; api if URL given), evidence pasted
2. Parser survives a fixture with 0 listings and one with 40
3. Failure returns last snapshot with stale=true and logs a decision-ready reason

## Audit focus
- Brittle selectors without fixture tests
- Depth aggregation off at 2% steps

## Tests required
- unit: page-parser.test.ts; integration: signals-client.test.ts
