# S-02 · Ledger extension: per-call metering, caller keys, treasury events, chain snapshots, savings metrics
Sprint 1.0 · Layer: L0 · Depends on: T-011 (done) · PRD: docs/PRD-1.0-sprint.md §4 T-2, §6

## Goal
The ledger can store what the gateway meters (real cost vs baseline per call), who called (caller keys), what the treasury did on-chain (events with tx hashes) and what it saw (chain snapshots), and can answer "how much was saved" with one query.

## In scope
- Extend `packages/core/src/ledger/schema.ts` (single source of truth; regenerate both dialects with `pnpm --filter @orbio-treasurer/core gen:sql`):
  - `usage_events`: add nullable `requested_model` text, `route_reason` text, `baseline_cost_usd` money, `caller_key_id` text (fk to `caller_keys`, nullable).
  - new `caller_keys`: `id`, `agent_id` (fk, nullable), `key_hash` text unique (sha256 hex), `key_prefix` text (`otk_` + 6 chars), `label` text nullable, `created_at`, `revoked_at` nullable. Append-only; revocation = new row with `revoked_at`? No — keep it simple and safe: `caller_keys` gets ONE guarded update `revokeCallerKey(id, at)` (only `revoked_at`, only null → value), mirrored by the append-only trigger allow-list.
  - new `treasury_events`: `id`, `agent_id` (fk), `at`, `kind` text in (`settle`,`claim`,`activate`,`buy`,`stake`,`mode_change`,`alert`,`dry_run`), `amount` tokenAmount nullable, `token` text nullable (`CREDIT`,`ORBIO`,`USDG`,`ETH`), `usd_value` money nullable, `tx_hash` text nullable (validated `^0x[0-9a-f]{64}$`), `meta` jsonb. Append-only.
  - new `chain_snapshots`: `id`, `agent_id`, `as_of`, `staked_orbio` tokenAmount, `settled_credit` tokenAmount, `credit_wallet` tokenAmount, `credit_api_available` money, `credit_api_used` money, `quote_credit_per_usdg` money nullable, `eth_balance` tokenAmount, `usdg_balance` tokenAmount, `mode` text, `rpc_url_host` text. Append-only.
- `LedgerStore` (types.ts) + both stores: `insertCallerKey`, `getCallerKeyByHash`, `revokeCallerKey`, `insertTreasuryEvent`, `listTreasuryEvents(agentId, limit)`, `insertChainSnapshot`, `latestChainSnapshot(agentId)`; `insertUsageEvent` accepts the new fields. Conformance suite (`conformance-suite.ts`) extended so SQLite and Postgres are tested identically.
- `packages/core/src/ledger/metrics.ts`: `savings(store, agentId, window: '24h'|'7d'|'all', now)` → `{calls, costUsd, baselineUsd, savedUsd, savedPct, byTier: {S,M,L: {calls, costUsd}}}` and `burnDaily(store, agentId, now)` → max(last 24h cost, 7-day daily average, ε=0.01) as decimal strings. Pure over store reads; `now` is an input.
- `supabase/migrations/005_sprint_ledger.sql`: the Postgres delta only (ALTER/CREATE + RLS + append-only triggers consistent with 002/003). Idempotent (`IF NOT EXISTS`).
- A `CallRecorder` implementation `LedgerCallRecorder` in `packages/core/src/ledger/recorder.ts` implementing the interface from `packages/core/src/router/recorder.ts` IF that file exists on your branch; if it does not (S-01 in flight in parallel), define the identical interface locally in `ledger/recorder-types.ts` with this exact shape and note it in Discovered:
  `interface CallRecord { at: string; agentId: string; callerKeyId: string|null; requestedModel: string; model: string; tier: 'S'|'M'|'L'; reason: string; promptTokens: number; completionTokens: number; costUsd: string; baselineCostUsd: string; latencyMs: number; status: 'ok'|'no_usage'|'upstream_error'|'treasury_empty'; error?: string }`, `interface CallRecorder { record(r: CallRecord): Promise<void> }`.

## Out of scope
- HTTP routes, router, policy, chain reads. Removing or renaming existing tables/columns. Touching `orders`/`key_meta` semantics.

## Acceptance criteria
1. Both dialects generated from `schema.ts`; `pnpm test` runs the conformance suite green on SQLite and on a real Postgres (local `initdb` cluster as in T-011; `TEST_DATABASE_URL`).
2. Append-only enforced: an UPDATE on `treasury_events`, `chain_snapshots`, `usage_events` fails in Postgres (trigger test) and the stores expose no update method for them.
3. `revokeCallerKey` can set `revoked_at` once; a second call throws; no other column changes.
4. `tx_hash` outside `^0x[0-9a-f]{64}$` is rejected at the store boundary with a typed error.
5. `savings()` returns exact decimal-string math on a fixture of 10 usage events (S/M/L mix) — expected values written by hand in the test, including `savedPct` = `saved/baseline` with 4 decimals and `0` when baseline is 0.
6. `burnDaily()` on empty history = `0.010000`; on 3 days of history = max(24h, 7d avg) — table-driven.
7. Migration 005 applies twice without error on the local Postgres.
8. No secret/key material stored: `caller_keys` holds only hash + prefix (test asserts the full key is absent from every column).

## Audit focus
Append-only trigger allow-lists (the single guarded update); decimal math (no float); UTC checks on the new timestamp columns; migration parity with gen-sql output; RLS on the new tables (anon read on nothing new except what S-08 will need: `treasury_events` and `chain_snapshots` readable when the agent is `public`).

## Tests required

## Discovered

- **`listUsageEvents` isn't in the ticket's explicit `LedgerStore` method list**, but `savings()`
  and `burnDaily()` are specified as taking `store` and reading `usage_events` — nothing else in
  the interface could serve that read. Added `listUsageEvents(agentId, { sinceAt? })` following
  the existing `latestTreasurySnapshot`-style read-method pattern. Flagging in case this should
  instead be phrased/shaped differently (e.g. the tick/policy ticket, S-06, may want its own
  windowed aggregate rather than raw rows) — easy to rename/extend later, nothing else depends on
  its exact shape yet.
- **`packages/core/src/router/recorder.ts` does not exist on this branch.** Per the ticket's own
  instruction for exactly this case, defined `CallRecord`/`CallRecorder` locally in
  `ledger/recorder-types.ts`, verbatim from the ticket text. If S-01 lands `router/recorder.ts`
  with the same shape, one of the two files should re-export from the other rather than the
  interfaces drifting — not done here since S-01 wasn't visible to this branch.
- **`caller_keys`' "second revoke throws" is enforced at the store boundary, not by a DB-level
  value-transition trigger.** The DB trigger (generated by the existing generic `mutable-guard`
  `WritePolicy`) only stops *other* columns from changing — it does not know `revoked_at` must
  go null→value exactly once, because `schema.ts`'s `WritePolicy` DSL has no concept of a
  column's *previous value* the way it does for "not deleted"/"no other column changed". Adding
  that would mean extending `gen-sql.ts`'s trigger generator (a change with a much bigger blast
  radius — it backs `agents`/`orders` too), which felt out of this ticket's "In scope" (schema.ts
  data + stores only). Flagging for audit/So: acceptable as app-layer-only, or worth a follow-up
  ticket to add DB-level defense in depth?
- **Pre-existing T-002/T-011 Postgres test files broke against a real cluster** once `schema.ts`
  gained the 3 new tables — `schema.postgres.test.ts`, `t002.tester.test.ts`,
  `t011.tester.test.ts` each hard-code a DROP list in their own `beforeAll` that didn't include
  `caller_keys`/`treasury_events`/`chain_snapshots`/`caller_keys_guard_write()`, so re-running
  001-003 (now containing `CREATE TRIGGER trg_caller_keys_guard`, no `IF NOT EXISTS` in Postgres)
  errored with "already exists" on a second run. Fixed by extending their DROP lists identically
  to `ledger-conformance.test.ts`'s. This is collateral upkeep from the in-scope schema.ts change,
  not new scope — CLAUDE.md #8/"fix what you broke."
- **This worktree's initial HEAD (4395c6d) was behind local `main` (b9afc8e)** — the commit that
  added `tasks/S-02.md` and `docs/PRD-1.0-sprint.md` itself. Had to `git checkout -b s-02 main`

  parallel worktrees (e.g. S-01's) hit the same thing.
